## Product Job

AudioGraph's MVP is a local-first desktop memory recorder for meetings, calls,
videos, and other computer audio. Its primary job is:

> Select what to hear, start once, receive trustworthy live notes plus a
> transcript, then review, export, and inspect exactly where the memory came
> from.

The durable path is source discovery and consent -> `rsac` capture -> Deepgram
ASR -> revisioned transcript -> automatic notes and temporal graph -> session
replay. Native and composed speech-to-speech agents are sibling modes after the
MVP, not the organizing principle of the main application.

Evidence:

- `README.md:10-23` and `docs/ARCHITECTURE.md:39-77` define the durable
  memory product separately from the realtime collaborator.
- `docs/backlog/handoff-2026-07-08-caad-10ac-wave.md` narrows the selectable
  MVP to Deepgram ASR plus LLM providers. The notes path does not speak by
  default; any optional TTS dispatch is separately registry-gated.
- `src/App.tsx:631-901` currently composes During, After, and Analysis.

## What Should Be Preserved

The current frontend has substantial proven infrastructure that a total
component rewrite would discard:

- Zustand state and Tauri command/event contracts.
- `NotesPanel`, `LiveTranscript`, `SeekTimeline`,
  `KnowledgeGraphViewer`, session logic, and the settings controller.
- Focus traps, skip-to-main, roving tab behavior, phase and recording
  announcements, humanized errors, sample preview, reduced-motion handling,
  tray integration, and the global capture shortcut.
- The token-bridged Tailwind v4 system governed by ADR-0009 and ADR-0016.

The recommended rewrite boundary is the application chrome and composition:
`App.tsx`, `ControlBar`, workspace layout CSS, Express Setup, and the
Settings overview. Existing data components remain the implementation units.

## Discovery failures and implementation status

### MVP selectability is not a universal UI invariant

At discovery, the generated registry marked deferred providers with
`ui_selectable=false`, but older actionable surfaces bypassed it:

- `ConversationModeControl.tsx:149-178` exposes native Gemini/OpenAI controls.
- `providerSetupModes.ts:282-345` still constructs Local and Native cards.
- `ProductModeSummaryCards.tsx:163-178` enables "Use this mode" for every
  unselected card, even when readiness is blocked.
- `providerSetupModes.ts:1305-1317` falls back to the first provider id when
  no selectable provider exists.
- `App.tsx:102-117` treats an OpenAI key alone as a runnable durable cloud
  pair, although Deepgram is the only selectable MVP ASR.

The current working slice fixes these bypasses at the backend command boundary
and mirrors them in the store and controls. The serial frontend suite passes 69
files / 938 tests. `audio-graph-da33` remains open until executed Tauri invoke
tests cover every content-bearing start. AWS named-profile readiness now checks
the passive local profile list and keeps setup visible when the saved name is
missing, without resolving the chain or performing provider egress.

### There is no true pre-capture workspace

`WORKSPACE_VIEWS` contains During, After, and Analysis and initializes to
During (`App.tsx:163-164,235`). Idle users therefore begin inside an empty
live cockpit. Audio sources and speaker controls remain mounted in every phase
(`App.tsx:728-732`) instead of forming a focused readiness step.

### Starting a useful session is fragmented

Capture and transcription are separate user actions with separate partial
guards. The UI exposes implementation stages rather than the goal "start a
note session." There is no atomic preflight for source permission, storage,
Deepgram, LLM, credentials, and data-egress policy, and no cross-stage rollback
if capture starts but processing fails.

Tracked by `audio-graph-10ff`.

### Diagnostics compete with the core task

`PipelineStatusBar` is globally mounted (`App.tsx:844`) and exposes six
pipeline stages plus turn, consumer, and writer state. Agent and token controls
remain first-class toolbar actions. During should carry one composite health
signal and disclose stage details only on degradation or in Inspect.

Tracked by `audio-graph-50e3`.

### Automatic and manual notes compete

ADR-0024 makes revisioned event-sourced notes primary and whole-session
synthesis a fallback. `NotesPanel` still gives "Synthesize notes" prominent
placement and renders separate synthesized prose beside materialized notes.
The fallback should move to an overflow action named "Generate prose summary."

### Privacy appears after capture, not during it

The detailed route panel appears only for loaded sessions in Analysis
(`App.tsx:624-627`). Live capture needs a content-free, exact provider and
boundary indicator.

Tracked by `audio-graph-8d18`.

### Loss of durability can be visually dismissed

`StorageBanner` reports stopped or failed writes but lets the user clear the
warning without proving recovery. A memory product must not look healthy after
canonical persistence stops.

Tracked by `audio-graph-a339`.

### Dynamic screen-reader output needs a runtime audit

The timer is a polite live region updated every second, transcript output
combines a live log with a nested partial live region, and the constantly
changing pipeline bar is itself `role=status`. Static unit tests cannot prove
this is intelligible in NVDA or VoiceOver.

Tracked by `audio-graph-8e51`.

## Recommended Information Architecture

### Ready

Own source selection, capture permission, Deepgram readiness, chosen LLM
readiness, storage health, privacy/data route, sample preview, and one
"Start note session" action.

### Live

Enter automatically after the atomic start succeeds. Make automatic notes the
primary surface, transcript/provenance secondary, and show only a compact
source, Stop, data route, elapsed time, and composite health signal.

### Review

Enter automatically after Stop or session load. Own durable notes, generated
summary, decisions/actions/questions, transcript, speaker/seek timeline,
session metadata, and export.

### Inspect

Nest under Review instead of making Analysis an always-equal global phase. Own
the temporal graph, provenance, data-movement ledger, projection status,
queue/backpressure diagnostics, and other engineering detail.

## Visual Direction

Concept: **studio tape meets temporal memory**.

The interface should feel like a precise field recorder that turns sound into
traceable memory, not a generic SaaS dashboard.

Palette:

- Console `#0C171A`
- Deck `#15272B`
- Fog `#DCE8E5`
- Phosphor `#75D8C4`
- Record `#FF6F61`
- Provenance `#91A8FF`

Typography:

- Restrained headings/wordmark: Bricolage Grotesque.
- Body and transcript: Atkinson Hyperlegible Next.
- Timing, source ids, and provenance: Spline Sans Mono.

Fonts must be bundled locally or replaced with metrically suitable installed
fallbacks; no runtime font CDN is acceptable for the desktop/privacy path.

Signature element: a **temporal spine** that extends the existing seek
timeline. Ready uses it to show source -> provider -> local-memory routing;
Live shows meaningful final/note/graph event ticks and health rather than a
decorative waveform; Review turns it into provenance-aware navigation.

## Verification Gates

- Fixtures: no key, partial key, rejected key, provider unavailable,
  permission denied, storage full, and full happy path.
- One action starts capture plus Deepgram processing; second-stage failure
  rolls capture back.
- Continuous speech produces useful notes before a pause; stop/reload restores
  transcript, notes, graph, route, and timeline deterministically.
- Screenshots: Ready, LiveNow, Review, and Inspect at 1440, 1024, and 768 pixels;
  dark/light; idle/loading/error.
- Keyboard-only, 200 percent zoom, forced colors, reduced motion, NVDA on
  Windows, and VoiceOver on macOS.
- Packaged Tauri smoke on Windows, macOS, and Linux for permissions, tray,
  global shortcut, export, and restart.

## Safety implementation checkpoint (2026-07-09)

- Historical Review now hard-disables Notes synthesis and Chat send because the
  current backend commands target the active session. English and Portuguese
  copy explains the boundary instead of silently mixing Review A with active B.
- The session data-route model is tri-state. Only valid same-session schema-v1
  lifecycle evidence with an ordered capture start and stop can support a
  no-egress result; empty, open, mixed, out-of-order, or future-schema evidence
  is Unknown.
- Express Setup and Sessions Browser contain immediate Tab/Shift+Tab from the
  initially focused dialog container and close on Escape from focused
  descendants.
- Focused verification passes 111 tests across seven files, TypeScript, and
  focused Biome. Real WebView/NVDA/VoiceOver evidence remains open.
